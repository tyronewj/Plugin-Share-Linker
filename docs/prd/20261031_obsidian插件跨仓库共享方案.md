Obsidian 本身没有"全局插件"这个开关——插件是按仓库隔离存在 `仓库/.obsidian/plugins/` 下的。想让多个仓库共用一份，只能在文件系统层面做目录链接：所有仓库的 plugins 指向同一个真实目录，一处安装/更新，全部生效。

## 先搞清楚哪些能共享、哪些不能

|项目|是否共享|位置|
|---|---|---|
|插件代码（main.js/manifest.json）|✅ 共享|`plugins/<插件>/`|
|插件自己的设置|✅ 跟着共享|`plugins/<插件>/data.json`|
|启用哪些插件|❌ 各库独立|`.obsidian/community-plugins.json`|
|主题文件|✅ 可共享|`.obsidian/themes/`|
|CSS 片段|✅ 可共享|`.obsidian/snippets/`|
|工作区布局|❌ 千万别共享|`.obsidian/workspace.json`|

两个要点：**data.json 就在插件目录里**，所以整目录链接 = 连设置一起共享，A 库改插件设置 B 库也跟着变；**启用列表在 community-plugins.json**，不在 plugins 内，所以各库仍能自己决定开哪些插件——这正好是你要的灵活性。

## Windows（Junction / 目录符号链接）

管理员身份打开 CMD：

```
mklink /J "D:\Obsidian\notes-work\.obsidian\plugins" "D:\Obsidian_Global_Plugins"
```

`/J`（目录联接）比 `/D` 兼容性更好、不强制管理员；同盘符时最稳。先把副仓库原有的 `plugins` 目录删掉或改名备份，否则会报 File exists。

## macOS / Linux（软链接）

```
cd ~/Obsidian/notes-work/.obsidian
ln -s ../../notes-main/.obsidian/plugins plugins
ln -s ../../notes-main/.obsidian/themes  themes
```

用**相对路径**，整个 Obsidian 文件夹挪位置时链接不会断；macOS 上别用 Finder 的"制作替身"，那是 alias，Obsidian 认不出来。

## 六个必踩的坑

1. **不要链接整个 `.obsidian/`**——`workspace.json`、窗口状态会互相打架。
2. 目标位置必须为空才能建链接，已有内容先搬进源仓库再删空目录。
3. 建完必须重启 Obsidian（或 `Ctrl/Cmd + R`），否则扫不到新目录。
4. 每个新仓库仍要手动关一次**受限模式**，这是 Obsidian 的安全设计，任何方案都无法预置。
5. 删链接时 `rm` 不要带 `-r`，否则会顺着链接把源文件一起删掉。
6. 放在 iCloud/Dropbox 里的仓库别这么做，云同步和链接容易冲突。

## 懒人替代：装个插件帮你做

不想碰命令行的话，社区已经有现成方案：**StoreSync**​ 把 `~/.obsidian-plugin-store` 作为共享库，新仓库几秒内自动接入，任一仓库装/更新插件全库可见，还支持一键 Unlink 还原（桌面端，macOS 验证过，Windows 未测试）；**Share Linker**​ 支持按插件逐个复制或建链接，适合只想共享一部分的场景；Windows 用户可以看 **Sync Settings for Windows**，用 profile 一键同步插件、主题、快捷键，且自动跳过 workspace。

脚本我打包好了，Windows 的 bat 改两行配置就能跑（支持把仓库文件夹直接拖到 bat 上），mac/Linux 的 sh 同理：

obsidian-global-plugins.zip

仓库在 3 个以上、插件超过十来个，这套五分钟的配置基本一次回本；只有两个库的话，手动装两遍反而更省事。
